# Schema and design decisions

## Conceptual mapping

The submitted EER diagram's total, overlapping USER specialization maps to
`app_user`, `author`, and `reviewer`, with shared primary keys for the roles.
AUTHORSHIP maps to `paper_author` with order and corresponding-author attributes.
The weak PAPER_VERSION maps to `(paper_id, version_no)`, with cascade deletion.
TRACKS, CONTAINS, HAS_SESSION, CHAIRS, COORDINATES, SUBMITS, and HAS_REVIEW map to
foreign keys. REVIEWER_POOL becomes `conference_reviewer`; ASSIGNED_TO is the
nullable `paper.session_id` reference.

All multivalued attributes become dependent relations: author research areas,
reviewer expertise, conference host names, and paper keywords. These are text
labels, not independent domain objects. Affiliation, country, room, and a track's
single research-area label remain scalar fields. No lists are comma-separated.

There is no material change to the conceptual entities or cardinalities.
Physical naming follows Appendix A, including `app_user` and
`conference_session`, avoiding ambiguous SQL names. Diagram spelling variations
are normalized (`is_corresponding`, `recommendation`). The sample-data-only
minimum-cardinality rules remain documented rather than implemented as deferred
triggers, as expressly permitted by Part 1.

## Columns, keys, and references

All columns are NOT NULL, including primary-key components, except `author.orcid`,
`paper.session_id`, `paper_version.change_note`, and `review.confidential_comments`.
The full column definitions are in `sql/schema.sql`.

| Relation | Primary key | Foreign keys | Other keys / checks |
| --- | --- | --- | --- |
| `app_user` | `user_id` | None | Unique `email` |
| `author` | `author_id` | `author_id → app_user.user_id` | Optional scalar ORCID |
| `author_research_area` | `(author_id, area_label)` | `author_id → author.author_id` | Labels unique per author |
| `reviewer` | `reviewer_id` | `reviewer_id → app_user.user_id` | Integer `years_experience >= 0` |
| `reviewer_expertise` | `(reviewer_id, area_label)` | `reviewer_id → reviewer.reviewer_id` | Labels unique per reviewer |
| `conference` | `conference_id` | None | `end_date >= start_date` |
| `conference_host` | `(conference_id, host_name)` | `conference_id → conference.conference_id` | Hosts unique per conference |
| `conference_reviewer` | `(conference_id, reviewer_id)` | `conference_id → conference.conference_id`; `reviewer_id → reviewer.reviewer_id` | Pool membership unique |
| `track` | `track_id` | `conference_id → conference.conference_id`; `coordinator_id → reviewer.reviewer_id`; `(conference_id, coordinator_id) → conference_reviewer` | Exactly one conference/coordinator per row |
| `conference_session` | `session_id` | `conference_id → conference.conference_id`; `chair_id → reviewer.reviewer_id`; `(conference_id, chair_id) → conference_reviewer` | `end_time > start_time` |
| `paper` | `paper_id` | `track_id → track.track_id`; `session_id → conference_session.session_id` | Five allowed statuses; scalar session gives at most one assignment |
| `paper_keyword` | `(paper_id, keyword)` | `paper_id → paper.paper_id` | Keywords unique per paper |
| `paper_author` | `(paper_id, author_id)` | `paper_id → paper.paper_id`; `author_id → author.author_id` | Unique `(paper_id, author_position)`; positive integer position; partial unique index on `paper_id WHERE is_corresponding` |
| `paper_version` | `(paper_id, version_no)` | `paper_id → paper.paper_id` | Positive integer version number, gaps permitted |
| `review` | `review_id` | `paper_id → paper.paper_id`; `reviewer_id → reviewer.reviewer_id` | Unique `(paper_id, reviewer_id)`; integer score 1–5; recommendation `accept`/`reject`; required date and nonblank comments |

Independent IDs are PostgreSQL `integer GENERATED BY DEFAULT AS IDENTITY`.
Seed IDs are explicit and each identity sequence is advanced afterward. Role IDs
are inherited references, not independently generated IDs. Positions, version
numbers, scores, and experience are integers. Corresponding-author flags are
booleans. Dates use `date`; session times use `time`; uploads use `timestamptz`.
Descriptive values and phone numbers use `text`. Phone numbers retain their `+`.

## Deletion actions

| Parent deletion | Behavior |
| --- | --- |
| Paper | Cascade to its authorships, keywords, versions, and completed reviews |
| Session | Set assigned papers' `session_id` to NULL; preserve the papers |
| User | Cascade to its author/reviewer profile, if references to those roles do not block the deletion |
| Author | Cascade research labels; authored papers block deletion through authorship FKs |
| Reviewer | Cascade expertise labels; pool memberships, reviews, coordinated tracks, or chaired sessions block deletion |
| Conference | Cascade hosts and pool memberships; existing tracks/sessions block deletion until explicitly removed |
| Track | Referenced papers block deletion |
| Pool membership | References from coordinator/chair composite FKs block deletion |

Unspecified FK actions are PostgreSQL's immediate `NO ACTION`. No foreign keys
are disabled. Removing a conference never cascades upward to its independent
users or reviewers. Tests demonstrate successful removal of an empty conference
after removing its empty track, retaining its reviewer and user.

## Enforcement matrix

| Rule | Automatic enforcement | Seed / validation |
| --- | --- | --- |
| Required primary keys, FKs, uniqueness, nullability, value checks | Database | Positive and negative tests |
| Completed reviews only | Required score, recommendation, comments, date; no draft-review state; database rejects blank comments | All 10 reviews complete |
| No self-reviews | `save_review` on insert/update; `replace_paper_authors` checks existing reviews | Tests cover both directions and reviewer/paper changes |
| Valid session assignments | `save_paper` checks acceptance and matching conference; `save_session` protects conference changes; `save_track` also protects track conference changes | Tests cover assignments, status/track/session edits, parent moves, and valid unassignment |
| Coordinator/chair belongs to conference reviewer pool | Optional composite FKs, implemented | All memberships valid; violations rejected |
| At most one corresponding author | Optional partial unique index, implemented | Violations rejected |
| At least one author and exactly one corresponding author | Implemented by `replace_paper_authors`; not globally enforced on raw inserts/deletes | All papers checked; helper rejects zero or multiple corresponding authors |
| Every user has at least one role; overlapping roles allowed | Part 3 user requests enforce minimum participation; raw SQL remains optional | All 10 seed users checked; all three role combinations present |
| At least one research/expertise label per profile | Part 3 profile requests enforce nonempty lists; raw SQL remains optional | Every profile checked |
| At least one host, track, pool member per conference | Seed-only minimum participation | Every conference checked |
| At least one keyword and version per paper | Part 3 paper requests enforce nonempty lists; raw SQL remains optional | Every paper checked |
| Current version is the highest version number | Derived convention, no stored current-version flag | Versions 1 and 3 make this observable |

## Assumptions

- A review is complete when all required review attributes are present; no review
  assignment or draft entity is introduced. The optional confidential comment
  can be NULL. A paper may retain completed reviews after withdrawal.
- Reviewer-pool membership is required for coordination and chairing. Assignment
  1 does not impose it on reviews, so no additional restriction is introduced.
  Amina reviews paper 1 without belonging to conference 1's pool.
- Email uniqueness uses PostgreSQL's case-sensitive text comparison. Emails in
  the seed are lowercase. ORCID is optional and has no additional uniqueness or
  format rule beyond the provided specification.
- Version numbers need not be contiguous. File locations are fictional paths;
  file content and uploads are outside Part 1.
- Conference/session calendar values are fixed in 2026; setup never reads the
  clock or uses randomness. Upload timestamps are UTC; session dates and times
  are local conference wall times. Seed sessions occur within conference dates.
- No unrequested deadline-order, author-position contiguity, room-overlap, or
  review-recommendation-versus-final-status rule is imposed.

## Part 2 view addition

`sql/accepted_paper_schedule.sql` adds the live `accepted_paper_schedule` view
without changing any Part 1 table or seed row. It returns paper ID/title,
conference ID/acronym, track name, session ID/title/date/start/end/room, chair full
name, and corresponding-author full name/email for accepted scheduled papers.
The view stores no duplicate data. Its creation, ordered query, and restoration
are documented in [part2.md](part2.md), and the combined export is
`sql/assignment3-export.sql`.
